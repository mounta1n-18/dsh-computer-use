## 1. 提示词盘点（模型到底看到了什么）

使用中注入：每条动作结果 40–150 字符；失败一次 35–200；`[提示]` 20–123；`【待回复】` 硬提醒 123/次；回合结束守卫 `TURN_NUDGE` 195；留言中继前缀 78。20 步会话的文本总量约 3.5–4.5K 字符，真正的上下文大头是**截图**（5–8 张，4–12K tok）。

可省的重复：activate 规矩散在 6 处、reply 规矩 6 处、热键 5 处、输出纪律 4 处、平面选择 4 处。**不建议再砍 description**：它已被 SKILL 覆盖但 SKILL 是按需加载，砍掉后模型不加载技能时只剩骨架，代价是重试率。真正该修的是三处**过期/矛盾文案**（SKILL.md 说琥珀色、label 参数、再按一次解除）。

## 2. 语言构成与选型

行数：Python 50.8%（11.1K 行）、ESM JS 32.7%（7.2K）、Markdown 12.2%、PowerShell 2.2%、CJS 0.3%。

- **Python**：Win32 注入/截屏/UIA/分层窗口/常驻服务/提示层。这些全是 ctypes + Pillow 的直接调用，Python 在这里是薄封装，不是性能路径；瓶颈从来不是它（截图 p50 82ms、点击 p50 38ms）。
- **JS**：工具 schema、入参校验、结果渲染、DSH 集成、IPC 客户端、CDP 浏览器自动化。它必须留在 Node——工具注册、attachments、CDP WebSocket 都在宿主进程里。
- **结论：不迁移。** 迁移唯一可能的收益是把常驻服务并入 Node 省一个进程，代价是重写 4400 行 ctypes 代码并丢掉 UIA/PIL 生态；耗时账本里 Python 侧占比 <10%。

## 3. 耗时账本（d469 实测会话，68 个 cu 步骤）

| 分段 | p50 | 占 cu 时间 |
|---|---|---|
| TTFT（首 token） | 840ms | 29.6% |
| 思考生成 | 515ms | 29.6% |
| 工具参数生成 | 117ms | 4.6% |
| 工具执行 | 74ms | 35.6%（其中 82% 是 hold/等待用户） |
| step 调度间隔 | 16ms | 0.6% |

- 真实 GUI 动作：p50 73ms、p90 271ms——**工具不是瓶颈**。
- 关思维链：每步均值省 0.86s、p50 0.52s、p90 1.92s；10 步任务省 5–9s（≈整轮 19%）。
- **TTFT 更值得动**：它随上下文膨胀（290K 上下文时 2.65s/步，占 cu 时间 50%）。压缩历史、少留截图，比关思考收益更大且无质量风险。

## 4. 思维链控制：为什么不做"单请求覆盖"

DSH 没有官方单请求 reasoningEffort 钩子：
- `agent/request` 已 @deprecated，改 effort 直接抛错；
- `llm/stream` 的 options 被 deep-freeze；
- `ConfigureCall` 是官方钩子，但 agent-loop 不传 configure；
- DeepSeek 适配器没有额外 header 钩子。

可行且官方的一条路：改**本会话**的 `model/selection`（`agent.model.select`）——下一 step 生效，界面"推理等级"实时跟着变，不写全局默认。

因此本轮实现：
- 新工具 `thinking_control(action=set|status|restore, effort=off|low|high|max, why?)`；
- cu 接管期间自动降为 `off`，交还时恢复用户原档位；鲸鱼下方状态字实时显示 `思考关闭/思考低/思考高/思考拉满`；
- 模型可在任意一步结尾自己调档，默认不思考，卡住再调高。

**未做**：面板里的「自适应思考」开关。它需要客户端插件（`conversation.input.model.options` 槽位）+ 宿主协议，属于新插件的工作量；当前能力已可用，开关等用户确认后单独做。

## 5. 消息积压与顺序（只读审计结论）

- 一轮进行中用户发消息，客户端默认 `queue`（Ctrl+Enter 才 `steer`）；`agent.followup` 不打断思维链、不打断工具循环，按 FIFO 每轮取 1 条。
- 工具结果按调用顺序落盘，实测 2361 次 tool/call 无一条用户消息插进同一批。
- cu 侧风险：hold 与宿主 relay 读同一个留言队列，原来会重复投递。本轮改为**认领（claim）**语义：先到先得，45s 未 ack 才放回队列。
