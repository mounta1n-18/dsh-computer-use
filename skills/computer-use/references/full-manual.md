# computer-use — 桌面操控

## 命令速查（先看这里，**不要去跑 -h 探索**）

所有命令都是同一条：
    python "$HOME\.dsh\skills\computer-use\scripts\cu.py" <子命令> [参数]

- **看**：shot / shot --long 800 / shot --region x,y,w,h / shot --window 名字 / windows / windows --all / rect 名字 / where / probe
- **动**：click X Y / type "文字" / key enter / key ctrl+s / paste "长文" / scroll X Y -3 / drag x1 y1 x2 y2
- **发**：post 窗口名 "文本" / post 窗口名 --image a.png
- **窗**：focus 名字 / launch 名字 / focus-cc / release
  - **launch 一律用中文显示名**（`launch 计算器`、`launch 设置`）。**别猜英文名**——
    `launch calc` 一定失败，白花一步。不确定就先 `apps 关键词` 查一次。
  - **要操作某个窗口：`focus 名字` + `shot --window 名字`，两步进入状态。**
    别先 `windows` / `windows --all` / 全屏 `shot` 探路——那三步纯浪费，
    而且全屏图比窗口图大得多、还夹带无关内容。
  - **打开快速设置面板用 `key win+a`**——比点托盘图标稳，还天然避开面板右下角那个齿轮。
- **批**：batch（stdin 一行一条，一个进程跑完多条）
- **其他**：clip / clip-set / 码 / 口径 / 静默

坐标一律 **0-1000 归一化**；--region 是唯一吃物理坐标的参数。

**不要为了"探索怎么用"去跑 -h / --help / apps / 列目录**——上面这张表就是全部常用的。
实测：一轮 T1 的 10 步里有 4 步浪费在探索 CLI 上。

**看一眼只花一个来回**：截图写死 --out 路径，读图放在**同一条消息**里：
    pwsh:       python "<插件目录>\python\cu.py" shot --out %TEMP%\cu\cur.png
    read_image: %TEMP%\cu\cur.png
同一次助手消息里的两个工具调用按「先写后读」执行，所以一个来回就能看到画面。
「先截一张、再单独调 read_image」是两次模型往返——一次观察白花一倍时间，这是最贵的浪费。
要并排看第二张图（前后对比）时，第二次换 --out 的新文件名，两张一起读。


**是补充层：能走 API / 命令行就别动鼠标。**

**整个任务只加载本技能一次**：后续每一步直接在 `run_code` 里用 `tools.pwsh` 调 `cu.py`，不要为单个点击、单次输入再调一遍本技能——正文已经在这里了，重复加载只费时间不增信息。

**一个工作流只用一个平面**：要么全程截图操控，要么全程走浏览器自动化 MCP（吃可访问性树，比截图省一个数量级的 token；按该 DSH 组合自己的 MCP 配置挂载），中途别换——换了窗口与会话状态对不上。要**真实屏幕**（任务栏、系统 UI、别的应用窗口一起入镜）只能用截图路线。

**要替用户对外说话（微信 / QQ / 钉钉这类）时，先加载 `im-chat` 技能**——身份坦白、隐私边界、被遥控时的意图判断、离席告知、以及各平台的操作要点都在那边。

**每次 `tools.pwsh` 的 `description` 写意图、不写机制**——它显示给人看：写"打开设置改通知"，别写"调 cu.click 四次"。

## 铁律：向用户说话之前，先 focus-cc

**任务结束、任务中断、遇到阻塞、阶段汇报——凡是要对用户开口，先跑一次 `focus-cc` 把 DSH 界面切到前台。**

否则你的话出现在用户看不见的地方，他还在界面那边干等，连画面都不敢切。

这条是"动手前那句『请勿触碰』"的**对称动作**：拿走了键鼠，就得还回来。收起键鼠 ≠ 还回来——你得让用户**看见**你。

自查：如果你已经连着做了好几步还没 `focus-cc` 过，用户此刻多半看不到你。

**唯一例外：正在 `watch` 的时候。** 监看要求目标窗口在最前，`focus-cc` 会把 DSH 界面拉上来盖住它——两条规矩直接打架，
你会把自己正盯着的画面弄丢。**DSH 没有推送工具**，所以等待期间不要抢焦点去汇报：
把话留到 `job_output` 返回（job 结算会主动唤醒你）或本轮结束时一起说。

## 开工前：先拿到用户同意，再碰键鼠

**默认必须先问**。除非用户这次就是明确让你操控键鼠（他主动要求的），否则动手前走 `ask_user_question`：

> 接下来我要接管鼠标键盘（预计 **N 分钟**），期间请不要碰鼠标键盘。
> 中途可能需要你扫码或输密码，到时会切回终端叫你。现在方便吗？

选项给足三条：**现在可以，开始吧 / 我还在用，稍后 / 你先做完再叫我**。

- 拿到"可以"再动手；选了后两项就**停下等**，别自作主张开始。
- **时长要给出具体数字**（按步数粗估，如"约 3–5 分钟"），别只说"一会儿"。
- 这一步不能省。接管键鼠会让用户正在做的事全部中断——不打招呼就拿走，跟抢方向盘没区别。

动手后说一句"已接管，请勿触碰"，视觉路线依赖屏幕静止。

## 坐标一律 0-1000（`--region` 是唯一例外）

`(0,0)` 左上，`(1000,1000)` 右下，`(500,500)` 正中。按"目标占屏幕宽高的比例"估，支持小数。填像素会被拒。

`--region x,y,w,h` 是唯一吃物理像素的参数（与 `rect` 配套）。裁剪后坐标原点变了，`shot --region` 会打印换算公式，照它算。

## 一轮 = 一个 `run_code` + 一次 `read`

**DSH 里没有 `bash` 工具——唯一能直接调的是 `run_code`，shell 一律走 `tools.pwsh`。**

**每个程序的开头照抄这两行，之后每次调用只写一行。这是硬要求**：实测 ds4.1 上
**10.2 ms / 输出 token**，样板每多 200 字符就多花约 2 秒；一次操作要来回 6 趟，
写胖了就是 6~8 秒的净损失。

```ts
const CU = '$HOME\\.dsh\\skills\\computer-use\\scripts\\cu.py';
const cu = (a: string, d: string) =>
  tools.pwsh({ command: `python "${CU}" ${a}`, description: d });
```

之后所有调用都是 `cu('<子命令>', '<给人看的一句话>')`：

```ts
await cu('shot', '截屏看当前桌面');       // 只有需要看的结果才 console.log 出来
await cu('click 500 500', '点屏幕正中');
await cu('type "文字"', '输入短文本');
await cu('key enter', '回车确认');
```

- **一次 `run_code` 里把这一轮要发的全发完**，不要一步一个工具调用——每次往返平均 **3.5 秒**。
- 下文所有 `cu('...')` 都指上面那两行定义出来的函数。

子命令与参数（就是 `cu()` 的第一个参数）：

```
shot                                  截图；再把打印出的路径交给 `read`
click 500 500                         点击（或 --right / --double / --triple）
scroll 500 500 -3                     滚轮，正数向上；也收 up/down/left/right
type "文字"                            短文本
key ctrl+s                            或 key enter / key alt+tab
shot --region 700,300,560,360         只看一块（像素），读小字用
```

`type` **只打字，不按任何键**——文本里出现换行或制表符会被直接拒绝。回车是"发送"，
必须显式写成单独一条 `key enter`，这样它在工具调用里看得见、拦得住。

其余：`move x y` / `hover x y`、`drag x1 y1 x2 y2 [--ms]`、`clip-set "文本"`、`where`、`wait`、
`shot --window 某窗口`、`post 某窗口 "文本"`。完整清单见 `cu.py -h`。

**不要 `read` 同一张截图两次**——每次 `read` 都按整张图重新计费，路径相同也不去重。要复看就重截一张。

## 四条纪律（每条都在实测里吃掉过几十秒）

1. **不做任务之外的事。** 清理截图、读技能文档、探索目录、列文件——**一律不做**。
   截图落在 `%TEMP%\cu\`，**脚本自己会清理旧的**，你一步都不要花在这上面。
   实测：微信收发那轮 34 步里，近一半是这类白工。
2. **不用 `--region` 盲试坐标。** 先用**一张全屏图**定位控件，再决定裁哪块细看。
   盲试一次 = 一次完整往返 ≈ **5 秒**。实测调滑块那轮 25 步里有 10 步在盲试。
3. **不要输出思考过程，只管下一个动作。**
   **不许写任何分析、推理、权衡**——在心里想完，直接给动作或结论。以下全部禁止：
   - 思考与分析（"因为…所以…"、"我推测…"、"考虑到…"、"看起来应该是…"）
   - 复述画面（"我看到屏幕上有一个…"）
   - 复述刚做过的事（"我刚才点了…"）
   - 自我确认（"让我确认一下…"、"再检查一下…"）
   - 计划清单（"第 1 步…第 2 步…"）
   - 过程解说与总结（"现在开始…"、"完成了…"）
   - 长篇收尾汇报：**最后的汇总不超过 3 行**（做了什么 / 结果 / 有没有要用户处理的）。
     实测 T2 那轮收尾写了 1,583 字 ≈ 400 token ≈ 2 秒，全是重复叙述。
   **实测：T3 只用 9 步却写了 13,017 个输出 token —— 每步 1,446 token，
   按 5 ms/token 算就是每步约 7 秒全花在这些字上。**
4. **看一眼就下结论。** 读图 / 读数值不求描写，只求**结论 + 动作**，一句话。
5. **一张图能支撑多个动作，就别一个动作截一次。** 只要动作**不改变布局**（连点同一排按钮、
   连续打字、滑块拖动），做完就接着做，不用每步都 `shot`。动作后只在
   **下一步依赖屏幕上有什么** 时才截图。实测：T3 调一个亮度滑块用了 4 张 `--region`，
   大半是多余的。
6. **滑块 / 滚动条：用 `drag` 一次拖到位，并且加 `--ms 150`。**
   `drag` 默认 800ms 是给"拖文件到资源管理器"这类**怕太快收不到中间事件**的目标用的；
   滑块只是要个落点，**150ms 足够**。
   - 别用"点击 + 方向键一点点挪"——实测 T3 点了 3 次 + 按方向键，仍然没对准。
   - 实测：T3 用了 3 次默认 drag（2.4 秒）+ 4 次 wait（2.5 秒），占 cu.py 总耗时的三成。

**总则：动作之后不要加 `wait`。** 下一步的 `shot` 本身就是同步点（要 ~200ms），
界面通常已经更新完。只有"下一步不截图、而目标还在动"时才 wait。
实测：T2 有一轮加了 **5 个 wait 共 4.3 秒**，全部白花。

**`wait` 单次不许超过 2 秒，一轮里最多两次。** 等应用/文档打开**不是**盲睡的理由——
先 `wait 2`，再 `shot` 看一眼；没开好就再来一轮 `wait 2` + `shot`。
实测：一轮里 3 次 `wait 10`/`wait 12` 白睡掉 **34 秒**，占那轮工具时间的四成；
而界面其实 3–5 秒就好了。
（2026-10-14 复盘：把"等就用截图代替"写成硬规矩后，反而出现几轮刷 20+ 张截图的异常长跑，
B1/B2 的步数与墙钟都退化——所以这里只限 `wait` 的量，不要用连拍截图代替等待。）

**别打扫别人留下的东西。** 打开的应用里若有历史遗留的空白文档 / 旧标签页，
**直接无视**——要新建就在旁边新建，不要去逐个 `ctrl+w` 关它。
实测：一轮里关了 8 个遗留标签页，花掉 13.5 秒，纯浪费。

**进入一个窗口，正确序列就两步**（实测正确执行的那轮只花 2 步，错误的那轮花了 5 步）：

    await cu('focus 微信', '切到微信')            // 一条就置前
    await cu('shot --window 微信', '看微信状态')   // 图更小、更聚焦

    ✗ windows / windows --all   ← 先用 focus，找不到窗口再用它
    ✗ rect 微信                  ← 只有真的要算 --region 时才用
    ✗ 全屏 shot                  ← 用 shot --window，省图像 token 也省无关内容
7. **能用命令读到的状态，就别靠截图读。** 截图只给"像什么"，命令给准确值：
   - 屏幕亮度 → `Get-CimInstance -Namespace root/WMI -ClassName WmiMonitorBrightness` 的 `CurrentBrightness`
   - 窗口在不在 / 叫什么 → `cu.py windows`
   - 剪贴板 → `cu.py clip`
   实测：T3 用 4 次 `--region` 反复试读一个滑块数值；同一个值一条 WMI 命令就拿到了。

## 盯：等外部事件，等待期间零 token

等一条回复、等一个下载跑完、等随机时刻发生的外部事件用它。脚本自己反复截图比对，
**等待期间你一个 token 都不产生**，所以可以等很久。

**三步，缺一不可——第二步最容易漏，漏了就等于没盯：**

```ts
const CU = '$HOME\\.dsh\\skills\\computer-use\\scripts\\cu.py';

// ① 起常驻盯：run_in_background 会立刻返回 jobId。它只入队，**不会叫醒你**
await tools.pwsh({ command: `python "${CU}" 盯 --window 微信`,
                   description: "常驻监看微信消息流", run_in_background: true });

// ② 叫醒器：同样后台起，再用 job_output(wait=true) 挂上去等它——这是唯一的唤醒方式
const s = await tools.pwsh({ command: `python "${CU}" 收 --wait 1800`,
                             description: "等微信画面出现变化", run_in_background: true });
await tools.job_output({ job_id: s.jobId, wait: true, timeout_ms: 600000 });

// ③ 醒来一次收干净，拿最新一帧的路径去 `read`
await tools.pwsh({ command: `python "${CU}" 收 --all`, description: "取走这一批变化帧" });

// 处理完，回头重新 arm 第 ② 步
```

> **`盯` 不会主动叫你。** 它不退出、不推送，只往队列里放东西。没有第 ② 步——后台挂着 `收 --wait`、却没有 `job_output(...wait=true)` 挂上去等它——你就会掉进"我以为它在盯、其实根本没人看队列"里干等。
> **实测踩过：对方连发七条，队列里躺了 17 条变化，我一条都不知道**，还是对方来问才发现。

- `盯` 起一个**常驻**盯：每次画面变化都把「帧 + 时间戳」压进队列、**立刻把基准换成新帧**，
  自己不退出。你正在想的那张**不会被后来的变化顶掉**，你想的期间来的每一张都还排在队里
  ——**不打断你正在进行的思考，也不漏空窗期里的消息**。
- `收` 按 FIFO 取一帧；`--all` 一次收干净（醒来后的常态，别一条一条取）。
  队列空时最多等 `--wait` 秒——**放到后台，它就是"叫醒器"**，这是让你被叫醒的唯一办法。
- 心里没底就 `瞧` 一下：`已产 N / 已取 M / 待取 K` + 常驻心跳。**`待取` 一直涨就说明你漏了。**
- **醒来要按顺序把这一批读完——画面不保证是累积的。** 弹窗出现又消失、提示一闪而过、
  列表滚过去就没了：**只看最后一张等于漏掉过程**。`收 --all` 会把这一批的帧路径按时序
  全列出来，照单逐张读。
  （**例外**：确实存在"老内容一直留在画面上"的累积型场景——聊天记录就是——那种可以只读
  结尾那张，并让中间帧进 `archive/` 留档。但**那是场景技能该给的捷径**（im-chat 有），
  不是这里的默认。别在通用场景自作主张省这一步。）
- 常驻到点会往队里补一条 `盯收尾` 事件，`收` 到它就知道不必再等。
- 同时盯好几处用 `--queue 名字` 分开；画面抖得厉害用 `--coalesce 2`（2 秒内只留最新那张）。
- **只在"等一个已知的、马上会来的信号"时才加 `--once`**（变了就交出一帧并退出）。
  长会话别用它：它退出到你 `read` 完之间那段空窗没人盯着，对方在这期间说的话你不知道来过。
  （默认常驻这件事是刻意反过来的——早先默认一次性、常驻要加 `--follow`，结果凭直觉敲
  `盯 --window X` 正好踩中这个坑。**直觉最短的那条路，必须是安全的那条路。**）

**`盯` 必须用 `tools.pwsh({ ..., run_in_background: true })` 起**——DSH 会立刻返回 `jobId`。
`收` 可以前台跑，`--wait` 别超过 540 秒；再长就用 `job_output(job_id, wait=true, timeout_ms=…)`
续等——单次等待上限 10 分钟，超时后再挂一次即可。

_`盯` 的其余 flag 看 `cu.py 盯 -h`；判据阈值、坐标三套、噪声量级看 `cu.py 口径`，
错误码看 `cu.py 码`——**脚本能回答的这里不重复**（省 token，也少一处会过期的抄本）。_

### 静默窗：你自己的操作不算"画面变了"

注入类命令（`click` / `type` / `paste` / `post` / `key` / …）**自己**把静默窗往后推 5 秒；
静默期内常驻盯只换基准、不压队列。于是你一边盯一边点鼠标、发消息，**不会把自己唤醒**。
关键是这件事由脚本自己做——你不需要记得调什么，也就不会忘。手动改：`cu.py 静默 [秒]`。

- 残留一处：**一次操作"调用瞬间"那一帧**——命令还没来得及设静默，界面已经先重绘了。
  实测一次操作爆发最多漏 1 帧，可以接受。
- 代价说清楚：静默期里真来的消息会被**一起吞掉**。所以**每次对外操作收尾自己核验一次**
  （顺带也确认结果）。这两条是配套的。

### 四条硬规矩

1. **盯的窗口要在最前，期间没人会盖它。** 屏幕监看抓的是"那块区域当前显示什么"，
   **不是"窗口的内容"**——被盖住时你盯到的是盖在它上面的东西。`--window` 会尽量自动置前，
   arm 时和唤醒时都复查并告警；**看到告警就先截图确认，别把这次唤醒当真**。
2. **别把 DSH 界面自己的窗口圈进去。** 它一边等一边输出，界面一直在重绘（工作时那个转圈状态行
   尤其明显），会把你唤醒成假警报。arm 时会算重叠比例并告警。
   （注：终端**最大化**时这条告警恒亮——它算的是矩形几何重叠，不是真实遮挡。终端在后台、
   目标窗口在前面时，这条可以忽略；判不准就 `--status` 看，或先截一张全屏。）
3. **框住你真正关心的那块。** 灵敏度是脚本内部按"变了多少像素"定的，**跟框多大无关**——
   所以框小并不会更灵敏。框小的意义是**把会自己变的东西挡在视野外**（时钟、进度条、动图头像），
   挡不住的再用 `--ignore` 圈掉。拿不准就先 `--timeout 30` 空跑一次，看它会不会误触发。
4. **别盯"会自己动的列表"。** 会话列表、消息列表这类东西会自己重排（置顶会话浮上来、
   未读角标增减、头像动图），每次都够得上触发线，你会被一堆与消息无关的唤醒淹掉——实测
   一次会话 12 次唤醒里 9 次是这类噪声。**盯内容区，不盯目录区**：聊天窗口盯消息流那块，
   不要盯左边那一列会话。

## 发消息进某个窗口：一条命令干完一轮

```ts
await tools.pwsh({ command: `python "${CU}" post 微信 "晚上一起吃饭吗"`,
                   description: "给微信发一条消息" });
await tools.pwsh({ command: `python "${CU}" post 微信 --image C:\\tmp\\a.png`,
                   description: "给微信发一张图" });
await tools.pwsh({ command: `python "${CU}" post 微信 "先打个草稿" --no-enter`,
                   description: "先在微信输入框打草稿" });
```

平时发一条消息要 4 次工具往返（截图→点框→输入→再截图验证），这一条全干完，只回一行结论。

- 结论是 **`已发送`** 时**不用再截图确认**，直接进下一步。
- 但要知道它到底保证了什么：**只是"文本进了输入框并回了车"**。对方账号停用、被拉黑、
  风控拦截时，目标程序会在气泡旁挂红标并给一行系统提示——**这些 `post` 看不见**。
  所以"发出去没有"是**目标程序自己的事**，核验规矩记在对应场景技能里（社交场景见 im-chat，
  那里有一条不花 token 的核验命令）。通用场景要确认就自己截一张全屏看。
- 结论是 **`存疑：…`** 时它会连那一帧的路径一起给你，那时才 `read`。
- 输入框不在底部中间就用 `--at x,y`（**窗口内** 0-1000）。

## 上下文预算（硬规则）

- `shot` 每次都打印"约 N 图像 token"。**先问这张图要干嘛**：找目标 / 看布局 → `--long 800`（图像 token 减半）；
  验证整屏状态 → 默认 1280。
- **读完图直接给结论和动作，不要复述画面。** 模型时延由输出 token 决定（实测 3~10 ms/token），
  "画面上我看到了一个计算器，标题是计算器，显示的数字是 0" = 几十个 token 白花；
  写"计算器已就绪，直接输入算式"就够。**这是这一步最大的一块省时。**
- **验证状态一律截全屏**，不要用 `--region` 判断"这件事成没成"。裁剪会漏掉关键信息——实测漏看过输入框里挂着的图片，误判成"没成功"，于是重复操作了三次，最后把目标程序搞卡死。
- `--region` 只用来**看清已知位置的细节**（读小字、确认某个控件上的字），不用来判断整体状态。
- **`--full` 最贵**——2560 宽会被下游压到 1568，白花 50%。全屏验证用默认 `--long 1280` 就够。
- **不要每步都截图**：一次观察里图像占九成开销，只在"下一步取决于屏幕上有什么"时拍。
- 同一目标试错超 3 轮、或预计超 30 步，派 subagent（组合里挂了 subagent 工具才可用）。截图多的活外包出去，主上下文只留结论。

## 批处理与安全边界

**DSH 里既不需要 `batch`，也不需要 heredoc**——`<<'EOF'` 在 pwsh 里是语法错误。
`run_code` 一个程序里顺序写多个 `await tools.pwsh(...)` 就是批量执行，中间还能插
`read`、按结果分支，比 bash 那套更强：

```ts
const CU = '$HOME\\.dsh\\skills\\computer-use\\scripts\\cu.py';
const cu = (a: string, d: string) =>
  tools.pwsh({ command: `python "${CU}" ${a}`, description: d });

await cu('click 300 420', '点第一行输入框');
await cu('type "2015"', '输入年份');
await cu('key enter', '确认这一行');
await cu('wait 0.5', '等界面稳定');
await cu('click 300 445', '点第二行输入框');
await cu('type "2016"', '输入年份');
await cu('key enter', '确认');
```

**安全**（不改变布局，可批量）：连点同一张表格里的格子、连续打字。

**不安全**（改变布局，之后必须重新截图）：开菜单、开对话框、切标签、滚动、启动应用、切焦点。做完就结束这一步，重新 `shot`。

## 验证：不只看图

截图只说明"窗口在显示什么"，文件系统才说明"实际发生了什么"。保存/导出/下载之后，
**在同一个 `run_code` 程序里回读**（用 `node:fs`，别绕 shell）：

```ts
await tools.pwsh({ command: `python "${CU}" key ctrl+s`, description: "在目标程序里按保存" });
await new Promise((r) => setTimeout(r, 2000));

const os = await import("node:os");
const fs = await import("node:fs");
const p = os.homedir() + "\\Documents\\report.xlsx";
console.log("saved:", fs.existsSync(p), fs.existsSync(p) ? fs.statSync(p).size : 0);
```

> 两个环境事实：`run_code` 里 `process.env` 是**空的**，取家目录要用 `os.homedir()`；
> 另外**别用 `python -c "…多行脚本…"`**——pwsh 会把里面的引号吃掉（实测踩过），要跑
> Python 片段就写个临时 `.py` 文件，或让 `cu.py --out <文件>` 落地再用 `read` 看。

## 交还键鼠：受阻时和收尾时都要明说

**唯一正确的交还方式**：跑一次 `focus-cc` 把 DSH 界面切到前台 → **打字明确告诉用户可以接管了** → 等回应。别把界面丢在后台只发一句就继续跑——用户看不见。

**中途受阻**（扫码、验证码、密码、风控、授权）：先 `focus-cc`，再调 **`ask_user_question`**，选项给足三条：**已完成，继续 / 我做不到，到此为止 / 用户不在，先停下**——别让"没有回应"被当成"继续"。问题里要写清**要他做什么、做完点哪个**。控制权回来后**必须重新截图再动手**，UI 可能已经变了。

**任务做完**（或你不打算继续做了）：`focus-cc`，打一句明确的接管信号，例如 **"做完了，你可以接管键鼠操作了"**，并报清三件事：做完了什么、还剩什么、有没有要用户处理的事。

**subagent 拿不到 `ask_user_question`。** 跑在 subagent 里就把阻塞如实报回主 agent 并停下，绝不要用一句文本提问冒充交接。

## 开应用 / 找窗口

窗口标题往往是文档名（`SKILL.md - Notepad`）而不是应用名，所以匹配时标题和进程名都会看。

```ts
const CU = '$HOME\\.dsh\\skills\\computer-use\\scripts\\cu.py';
const cu = (a: string, d: string) =>
  tools.pwsh({ command: `python "${CU}" ${a}`, description: d });

await cu("apps 计算器", "查开始菜单里有哪些匹配的应用");   // launch 收名字或 AppID
await cu("launch 计算器", "启动计算器并置前");
await cu("windows", "列出可见窗口和能否注入");
await cu("windows --all", "连隐藏窗口一起列");             // 托盘里的会标出来
await cu("rect 计算器", "读窗口位置，算 --region 用");
await cu("focus notepad", "把记事本精确切到前台");
await cu("focus-cc", "把 DSH 界面切到前台给用户看");
```

- `apps` 不带关键词会吐几十行，**先按关键词过滤**，别把目录整个拉进上下文。
- **把筛出来的候选打印出来看一眼**——选错应用只有你自己能发现，脚本只保证启动本身成功。
- **切换已经打开的应用用 `focus`，别用 `launch`**：`launch` 会先起进程，它不是切窗口的手段。
- **"列表里没有" ≠ "没开"。** 被收进托盘的程序不会出现在可见窗口列表里（`IsWindowVisible` 为假），
  `focus` 自然也找不到。**先用 `windows --all` 确认它是不是还活着**——别因为找不到就重启它：
  不少程序（尤其聊天软件）重开的新实例会要求重新登录 / 扫码，而你本来就在登录状态。
  唤出托盘里的程序只能靠用户点，或按场景技能里记的办法。
- `launch` 返回 `accepted_unverified` = 没等到稳定的新窗口（可能本来就开着），不要重复启动。
- **打开应用只有一种写法，照抄，不要变形**：

  ```python
  launch 计算器        # 然后直接干正事
  ```

  - `launch` **内部已经等到稳定窗口出现并置前**。返回 `status=ready` 就是好了。
  - **不要再 `wait`、不要重复 `launch`、不要用 `windows` / `shot` 去复查。**
  - 只有返回 `accepted_unverified` 才是没等到；名字报 `CU_APP_NOT_FOUND` 才是名字不对。
  - 实测：一轮 T1 里重复启动 3 次 + 3 次盲等，cu.py 段从 5 秒涨到 **20.4 秒**（占整轮 50%）。
- **`focus-cc` 靠进程名找 DSH 前端**：桌面应用是 `DeepSeek Harness.exe`，终端里跑 `dsh` 就是那个终端。用户若在浏览器里看 `dsh web`，用 `cu.py focus-cc "<窗口或标签页标题子串>"` 指定——猜错窗口等于用户什么都没看见。
- **`focus-cc` 报 `CU_MINIMIZED` 或找不到窗口时**：DSH 桌面应用会被收进**系统托盘**，
  此时任务栏上没有它的按钮、`Alt+Tab` 也切不出来。找回来的办法：
  点任务栏托盘的 `^`（显示隐藏的图标）→ 点**鲸鱼图标**（DeepSeek 的 logo）→ 窗口就回来了。

## 剪贴板

```ts
await cu('paste "一千字的长文"', '把长文贴进当前窗口');  // 写剪贴板 + Ctrl+V，比逐字注入快几百倍
await cu('copy', '读当前选中的内容');                   // Ctrl+C 并返回选中内容
await cu('clip', '读剪贴板');
```

`paste`/`copy` 默认还原你的剪贴板。`paste` 是 Ctrl+V 之后约 0.08 秒就写回旧内容——Excel 大范围粘贴这类异步读剪贴板的应用可能来不及，遇到就加 `--keep`。

`copy` 在"剪贴板没有变化"时报 `CU_NO_SELECTION`（没选中内容，或焦点不在目标窗口），**不会**把旧剪贴板当成选中结果回给你。

## 长按修饰键与拖拽

Ctrl+拖拽、Shift+点选多行用 `key-down ctrl` / `key-up ctrl`，**两者必须在同一个 `cu.py batch` 进程里**——或者一个 `run_code` 程序里连着发两条 `tools.pwsh`，中间别插别的工具调用。分成两个进程的话，中间任何一步失败都会让修饰键 latch 住——之后每次点击都自带 Ctrl，而且**不会报任何错**。batch 异常退出时会自动松开本进程按过的键；怀疑残留就跑 `cu.py release`（它连鼠标键一起复位）。

拖拽默认 800ms 走完全程，不是瞬移：资源管理器、Outlook 这类拖放目标收不到太快的中间事件，表现成"拖了没反应"。要更快用 `--ms`。

## 必踩的坑

1. **坐标一律现读，不跨截图缓存。** 分辨率**和 DPI 缩放**都会变，改了之后窗口位置、滚动位置、页面布局全作废。
2. **`★UIPI` 窗口点不动**：目标以管理员运行时完整性级别高于本进程，系统**静默丢弃**注入——不报错，只是没反应。`windows` 会标 `★UIPI`，`focus` 会直接拒绝。Ctrl+Alt+Del 是系统保留键，注入无效。
3. **只给"有副作用的动作"补一张 `shot` 确认**——发送、删除、提交、保存、覆盖这类**做错了收不回**的。
   **普通点击 / 打字 / 切换焦点不用每步确认**（那是第 5 条要避免的浪费）：
   下一步是另一个已知位置的点击时，直接点下去就行。
4. **注入精度是 0 像素，误差全在"看图估坐标"。** 估不准就上 `--region` 放大。
5. **黑帧分两种**：看到 `[CU_BLACK]` 读它下半句——"不在可输入桌面"（锁屏/UAC）就**停下叫用户**，重试注入没有用；只是全屏独占程序就换个方式验证。裁剪区本来就黑是常事。
6. **取中文会乱码**：子壳走 GBK，`python` 一律加 `-X utf8`。`python -c "…"` 的引号在 pwsh 下还会被吃掉，多行脚本改写临时 `.py` 文件。
7. **不要猜快捷键。** 同一个键在不同程序里行为完全不同，**"同一个键在某个软件里到底干什么"
   属于那个软件的专属知识，记在对应的场景技能里**（例如 im-chat 记了微信的）。拿不准就先查或
   先小范围试。要清空输入框用 `key ctrl+a` 再 `key delete`。
8. **不要 hide / show / 最大化 / 还原你正在驱动的窗口。** 脚本自己也守这条：遇到最小化的窗口它会报 `CU_MINIMIZED`，不会替你 ShowWindow。Chromium 内核的程序（Electron 系、各家聊天软件）带着重草稿做窗口重排可能直接卡死。
   **但"用鼠标点任务栏/托盘图标"把它拉起来是安全的，也是正路**：先 `shot` 定位图标 → `click` → 再 `focus`。脚本不做 ShowWindow，不等于你不能点。只有点不动（找不到图标，或已收进托盘、溢出菜单里也没有）才去叫用户。
9. **失败先看 stderr 的 `[CU_XXX]` 码**，按码决定下一步，别瞎试。`提示：退出码在 DSH 的 pwsh 下不可靠`——只要 cu.py 往 stderr 写过东西，pwsh 自己就以 1 收场，把真实的 2 盖掉（实测）。**认 `[CU_XXX]`，别认退出码。** **一次没成先看全屏截图，别重复同一动作**——重复三次可能把目标程序搞崩。

10. **Windows 11 快速设置面板右下角有个齿轮图标——那就是"打开设置"。**
    别往面板右下角点。误点一次就会拖起又慢又重的「设置」应用（`systemsettings.exe`），
    之后整轮都受它拖累（实测：T3 场景被它连累过两轮）。
    改亮度/音量一律走**任务栏右下角展开的快速设置面板**，不要走「设置」应用。

11. **`shot --window X` 会自动把 X 置前再截**（屏幕截图抓的是"那块区域当前显示什么"，
    不是"窗口的内容"；窗口被盖住时以前会**静默截到别的东西**）。
    置前仍被挡住会报 `CU_COVERED`——那不是让你绕路，
    是让你先 `focus` 它、或把挡着的窗口挪开。**别改用 `--region` 绕过它**，那又会截错。

> 要给本技能做 benchmark 或改它：先看 `references/benchmark-指南.md`（很短，全是踩过的坑）。

## A1 常驻服务与传输环境层

`python/cu_server.py` 是常驻服务：一次拉起，长连接收发。CLI（`cu.py`）仍完整可用，是降级/调试路径。

**为什么值得**：冷启动约 150–300ms，每条命令都付一次；常驻后只剩一次管道往返。
更要紧的是**状态**（凝视队列、修饰键 latch、静默窗）从"临时文件在进程间传"变成内存对象。

**传输**由 `DSH_CU_*` 环境变量决定，字段结构与豆包 `GacTransportConfig` 对应但命名独立：

| 变量 | 含义 | 默认 |
|---|---|---|
| `DSH_CU_TRANSPORT` | `named_pipe` / `uds` / `tcp` | Windows 命名管道，其它平台 UDS |
| `DSH_CU_ENDPOINT` | 管道名或 socket 路径 | `\\.\pipe\dsh-computer-use` |
| `DSH_CU_PORT` | tcp 端口 | 无 |
| `DSH_CU_FALLBACK_TRANSPORT` / `DSH_CU_FALLBACK_PORT` | 兜底传输（目前只支持 tcp） | 空 |
| `DSH_CU_CONNECT_TIMEOUT` | 连接超时秒 | 5.0（有兜底时主路只给 0.5） |
| `DSH_CU_IO_TIMEOUT` | 单请求 IO 超时秒 | 30 |
| `DSH_CU_HOME` | 运行目录（审计/日志/socket） | `%LOCALAPPDATA%\dsh-computer-use` |
| `DSH_CU_PYTHON` | 指定解释器绝对路径 | 自动探测 `py -3` → `python` |
| `DSH_CU_LAZY` | `1` = 首次调用才拉起服务 | 空（加载即拉起） |

**帧格式**：`[u32 BE 长度][u8 类型][载荷]`；类型 `0`=JSON、`1`=PNG、`2`=日志。
图片走独立二进制帧，不做 base64（省 33% 拷贝）。

**不重发**：写/读失败后本次请求直接失败，**绝不在新连接上重试**——对端可能已经执行过，
重试等于把一次点击变成两次点击。客户端只标"不可恢复"，并在**下一个**请求前重连。

**单实例**：主判据是"端点探测"（能 ping 通就说明已有人在服务），锁文件只兜竞态。
复用的服务由**先启动的**实例拥有；后来者 dispose 时**不杀**它。

## A2 多步执行：batch 与 eval

- `computer_use{action:"batch", commands:[...]}`：一次跑多条 CLI 行，遇错默认停
  （`continueOnError:true` 继续）。返回逐条结果 + 汇总。
- `computer_use{action:"eval", code:"..."}`：在服务端跑一小段 Python。命名空间预绑
  `cu / os / sys / time / json / re / pathlib / math / subprocess`，可直接
  `cu.click(...)`、循环、条件判断、读文件。适合"一次调用干完一串事"。
  - 超时回 `CU_EVAL_TIMEOUT`。**线程无法强杀**，真挂住了用 `server_restart` 回收。
  - 它跑在服务进程里：能调全部 cu 能力，也能读到服务内存状态（队列等）。

## A3 元素级（UIA）：ref 与动作

`state-capture` 用 UI Automation 读出窗口树，给每个"有语义/可交互"的节点编号
`e1 / e2 / …`（返回带 role/name/value/rect/patterns）。之后：

```
element e12 --invoke          # InvokePattern
element e12 --set-value 文本   # ValuePattern
element e12 --toggle          # TogglePattern（幂等：已经是目标态就不再切）
element e12 --select          # SelectionItemPattern
element e12 --expand / --collapse / --scroll-into-view
element e12 --set-range-value 50
element e12 --get patterns    # 看它支持哪些模式
element e12 --click           # 最后手段：算中心点走真鼠标
```

**边界（必须知道）**：

- ref 只对**本次快照**有效。界面一变就重新 `state-capture`；旧 ref 报 `CU_ELEMENT`。
- 元素拒绝某个模式是正常现象（不是所有控件都实现全部 pattern）：按 `--get patterns`
  换一个；最后才退回坐标点击。
- 自绘界面（游戏、部分 Qt/Electron）不暴露可访问性树 → `CU_ELEMENT`，退回 `shot`。
- 实现是一个常驻 PowerShell 子进程（`.NET UIAutomationClient`）：ref 要跨调用存活，
  元素对象就必须一直活着。它带墙钟预算（默认 15s），超时截断并标 `truncated`，
  **不会**把服务挂死。
- UIA 调用在目标进程忙时会长时间阻塞（不可中断），所以预算与超时是硬要求，不是优化。

## A4 Windows 虚拟桌面

对齐的是"Windows 自带虚拟桌面（Win+Tab 那个）"。**注意**：豆包的
`switch_desktop('main'|'pip')` 不是它——`pip` 是豆包自己沙箱的 PiP 会话桌面，
本机没有对应概念，所以 `target:"pip"` 一律 `CU_VDESKTOP_UNSUPPORTED`，不瞎映射。

| path | 能做什么 | 真实性 |
|---|---|---|
| `com_public` | `desktop_current`（前台窗口所在桌面 GUID） | 稳，`IVirtualDesktopManager` |
| `com_internal` | 列表 / 按序号切 / 新建 / 关闭 | **多数机器拿不到** |
| `hotkey` | 按方向切（`Win+Ctrl+←/→`） | 稳，最推荐 |
| `unsupported` | 明确说做不到 + 手动办法 | 诚实兜底 |

**本机实测**：`ImmersiveShell` / `VirtualDesktopManagerInternal` 全部
`0x80040154 (REGDB_E_CLASSNOTREG)`、IID 全部 `E_NOINTERFACE`；公共 COM 可用；
热键可用（用 DWM `cloaked` 属性验证）。所以这台机器上：

- `desktop_current` → 真实 GUID ✔
- `desktop_switch{direction:"left|right"}` → 热键路径 ✔
- `desktop_list` → `available:false`（**不编造列表**）
- `desktop_create/remove` → `CU_VDESKTOP_UNSUPPORTED` + 手动办法（**不代替你按热键**）

**安全护栏**：内部 COM 拿到接口后先做校验调用（`GetCount()` 必须是 1..64 整数、
`GetDesktop(0)` 必须 data1≠0）；校验不过或异常 → **本进程内永久禁用**内部 COM，
回落热键。绝不在未校验的 vtable 偏移上调用——那是会崩的。

可选 `desktop_list{discover:true}` 按方向走一圈、用 GUID 去重反推数量，走完回到原位；
默认关闭（会短暂切屏）。

## A5 环境自检与安装引导

- `cu.py doctor` / `computer_use{action:"doctor"}`：逐项检查解释器、pillow、pywin32、
  屏幕/DPI、可输入桌面、前台窗口注入能力、剪贴板、审计目录、UIA 子进程、虚拟桌面、
  浏览器 CDP 端点。必需项 FAIL 时给**可直接粘出去跑的**修复命令。
- `cu.py setup` / `computer_use{action:"setup"}`：只**打印**安装命令；加 `--install`
  （或 `autoInstall:true`）才真执行。自动改用户 Python 环境属于偏重的不可逆操作，默认不代劳。
- 审计日志：`%LOCALAPPDATA%\dsh-computer-use\audit.jsonl`，每个注入类动作记
  `attempted → completed|rejected` 三态。**只记参数摘要**（字符串截 80 字符，
  `type` 只记 `chars=N`），不记正文、不记剪贴板内容。2MB 滚动。

## A6 结果状态与失败处置

每条工具结果带 `status`（对齐豆包 envelope 的分类）：

| status | 含义 | 该怎么办 |
|---|---|---|
| `ok` | 成功 | 继续 |
| `invalid_action` | 参数/名字不对 | 按提示改参数，**别重复同样的调用** |
| `state_changed` | 界面变了（遮挡/最小化/元素失效） | 重新观察，**别用旧坐标/旧 ref** |
| `blocked` | 系统级限制（UIPI/安全桌面） | 停止注入，请用户接管 |
| `timeout` | 超时 | 换策略或 `server_restart` |
| `error` | 其它 | 看 `[CU_XXX]` 码 |

`CU_IPC`、`CU_PROTOCOL`、`CU_EVAL`、`CU_EVAL_TIMEOUT`、`CU_AUDIT`、`CU_ELEMENT`、
`CU_NO_SIDECAR`、`CU_DEP_MISSING`、`CU_VDESKTOP_UNAVAILABLE`、
`CU_VDESKTOP_UNSUPPORTED`、`CU_VDESKTOP_PARTIAL`。

## A7 顺手对齐的输入校验（来自豆包 `_validation.py`）

- 键别名：`arrowleft/arrowright/arrowup/arrowdown` → `left/right/up/down`，
  `escape→esc`、`return→enter`、`control→ctrl`。
- `scroll` 数值必须非零、有限、∈[-10,10]；取整后为 0 时按**取整前**的符号取 ±1
  （`0.4` → `+1`，`-0.4` → `-1`）。错误码 `CU_SCROLL_DELTA`。
- `hotkey` 必须**每个键分开传**：`["ctrl","s"]`。传 `["ctrl+s"]` 直接
  `CU_BAD_HOTKEY`——否则会静默变成"打了一串字符"。
- `wait` 单位是秒，拒绝布尔；`wait(1000)` 报 `CU_WAIT_SECONDS` 并提示先除 1000
  （本实现上限 600s，比豆包 180s 宽；更久的等待该交给后台 job）。
- 截图做 **PNG 三重校验**：签名 + `IHDR`(长度 13) + `IEND` + PNG 自身宽高必须与声明一致。
  坏图直接 `CU_SHOT_FAIL`——模型不会说"这图是坏的"，它会照着半张图推理。
